## 1. 技术约束（不可违反）

| # | 约束 | 为什么 |
|---|---|---|
| 1 | **纯静态、零依赖、零构建**。禁止外部 CDN、禁止 npm 包、禁止构建工具 | 断网也要能用；家庭场景没有 CI，越简单越活得久 |
| 2 | **全部相对路径** | 部署在子目录也能跑 |
| 3 | **`file://` 下也要能用** —— 所以注册表是 `catalog.js` 而不是 `.json` | JSON 会被 CORS 拦掉 |
| 4 | **孩子端不得出现任何家长控件**（19 个 id 的红线） | 物理隔离，孩子翻不到设置 |
| 5 | **模块 id 三处必须一致**：`catalog.js` 的 `id`、模块页 `data-module-id`、`module.json` 的 `id` | 不一致会导致进度上报丢失 |
| 6 | **默认零联网**：不开多端同步时，一个网络请求都不发 | 隐私 + 断网可用 |
| 7 | **不改已有产物目录**（如 `一年级数独/`），新能力用 catalog 引用或新目录叠加 | 已验证的东西别动 |
| 8 | **同一条消息里不要对同一文件发两次编辑** | 后一次会覆盖前一次，静默丢改动 |
| 9 | **失败必须可见**：静默失败是本项目最贵的一类坑 | 见 §10 |

## 2. 架构总览

```
                          ┌───────────────────────────────────────┐
   孩子端 index.html  ────┤  student.js   界面：首页/课程/错题/成就/作业
   家长端 parent.html ────┤  parent.js    界面：门禁/明细/作业录入/同步设置
                          └───────────────┬───────────────────────┘
                                          │  都用同一份「核心层」
                          ┌───────────────▼───────────────────────┐
                          │  core.js  数据层 + 业务逻辑 + 错题本      │
                          │           + 作业解析 + 事件层 emit()      │
                          └───────┬───────────────────┬───────────┘
                                  │                   │
                       localStorage(xyb.v1.*)    emit() 时若有同步
                                  │                   │
                          ┌───────▼───────┐   ┌───────▼──────────────┐
                          │  浏览器本地    │   │  sync.js  多端同步层  │
                          └───────────────┘   └───────┬──────────────┘
                                                      │ HTTP
                                          ┌───────────▼──────────────┐
                                          │ server/server.py  数据服务 │
                                          │ 只追加事件 + 按 id 去重     │
                                          └──────────────────────────┘

   内容模块 modules/<id>/index.html ──引入──> xyb-sdk.js
        └─ 通过 localStorage 的 inbox 队列 与 核心层 通信（模块是独立页面）
```

**关键设计**：模块是**独立页面**，拿不到工作台的 JS 对象。所以 SDK 用
"写 inbox 队列 → 工作台回来时消费"这条**跨页面数据通道**，而不是函数调用。

`emit()` **运行时**才去调 `XYBSync`，所以脚本加载顺序必须是：

```
core.js  →  sync.js  →  界面层（student.js / parent.js）
```

顺序错了不报错，只是同步静默不工作。

## 4. 数据模型与事件

### 4.1 本地存储（`xyb.v1.*`）

| 键 | 内容 |
|---|---|
| `profile` | 昵称、头像、星星、连续天数、最后活跃日 |
| `settings` | 每日目标、休息间隔、护眼开关、音效开关 |
| `progress` | `{ 模块id: {status, done, total, stars, asked, right, timeMs, visits, lastAt} }` |
| `log` | 学习流水（上限 500） |
| `achievements` / `hidden` | 徽章获得时间 / 家长隐藏的模块 |
| `mistakes` | 错题（上限 300，去重键 `mid\|q`） |
| `homework` | `{ 日期: {raw, blocks:[{title, cls, tasks:[{text, full, icon, doneAt, due}]}]} }` |
| `guard` | 家长密码哈希 + 失败次数 + 锁定截止时间 |
| `session` / `inbox` | 跨页面会话 / 模块上报队列 |
| `cloud` / `outbox` / `events` / `deviceId` / `seq` | 同步相关（关同步时后四个不存在） |

### 4.2 事件（同步的最小单位）

`core.js` 的 `emit(type, payload)` 把每次**状态变更**记成一条事件：

| 事件 | 语义 |
|---|---|
| `progress` | 内容进度变化 |
| `log` | 学习流水 |
| `profile` / `settings` / `hidden` | 档案、设置、显隐 |
| `achievement` | 拿到徽章 |
| `mistake` | 错题新增/订正/删除 |
| `hw` | 作业记录新增/重解析/**某条任务打勾** |
| `checkpoint` | 检查点（导入快照、重置、回滚）——**之前的历史被它取代** |

**不变量**：同一批事件 + 同一顺序 ⇒ 同一状态。
这是整个同步方案的地基，改 `apply()` 时必须守住（见 §5）。

## 5. 多端同步机制（改之前先读 `服务端数据同步设计.md`）

**一句话**：服务端**不做业务合并**，只按到达顺序追加事件、按 `id` 去重、分配 `rev`；
客户端每次用「服务端事件 + 本地 outbox」**重算**一遍状态。

```
设备 A                   服务端                     设备 B
  │  本地事件 ──追加──▶  events.jsonl（去重 + rev）  ◀──追加── 本地事件
  │  ◀──拉取全部事件──┐                          ┌──拉取全部事件──▶
  │                  │                          │
  └─ rebuild(): 用「服务端事件 + 本地未发送的事件」重算状态 ─┘
```

- **回滚** = 服务端截断日志 + `gen+1`；客户端发现 `gen` 不一致 → 丢弃本地缓存全量重拉
- **口令不上网明文**：客户端把 `sha256('xyb::' + 口令)` 当 Bearer；服务端只存哈希
- **`http://` 是非安全上下文**，浏览器不给 `crypto.subtle`，所以 `sync.js` **自实现了一份 sha256**
  —— **改它必须验与 Python `hashlib` 结果一致**，否则鉴权会静默全挂
- **`ackIds` 不能删**：服务端要把"重复件的 id"也回报，客户端才能清队列。
  否则「已落盘但响应在回程丢了」的事件会被**永久重传**

## 6. 开发环境

```bash
# 起个本地服务（推荐，别用 file://）
python -m http.server 8080
```

跑测试需要 **jsdom**：

```
set NODE_PATH=<装了 jsdom 的 node_modules 目录>
node _build/smoke_test.js
```

`verify_all.py` 会自动探测 node 与 node_modules 的常见位置，也可以用环境变量指定：

```
XYB_NODE=<node.exe 路径>
NODE_PATH=<node_modules 路径>
```

部署脚本需要 **paramiko**：

```bash
pip install paramiko
```

## 7. 改代码的固定动作

### 7.1 验证关卡（一条命令）

```bash
python _build/verify_all.py            # 静态四关
python _build/verify_all.py --full     # 再加服务端 API + 线上终验
```

四关分别是：

| 关卡 | 抓什么 |
|---|---|
| `new_module.py --check` | 注册表标"已上线"但文件不存在 / 标"规划中"却有文件 |
| `check_refs.py` | JS 里 `getElementById` 的 id 是否存在、**孩子端是否混进家长控件**、模块 SDK 是否接入 |
| `smoke_test.js` | jsdom 里跑**真实交互**：渲染、筛选、打勾、时长结算、错题、门禁、作业、声音链路 |
| `smoke_sync.js` | 两台**真实设备**（内存假服务端）跑收敛、断网补交、重传幂等、回滚 |

**为什么不能只跑 `node --check`**：它查不出"事件绑定失效"—— 本项目踩过这个坑
（语法全过、按钮全死）。同理查不出"同步静默丢数据"、"设备不支持语音时一声不吭"。

### 7.2 新增测试用例

冒烟测试用 `ok(...)` / `eq(...)` 断言，按域分段（`[A1]`~`[D]`）。
写用例时的两条经验：

- **拿真实数据当用例**：作业解析器的 4 个坑全是真实原文暴露的
- **假依赖要能注入**：`bootModule(file, {scripts, speech, audio, seed})` 可以往 jsdom 里塞
  假 `speechSynthesis` / 假 `Audio` / localStorage 种子，用来复现**设备侧的失败分支**

### 7.3 部署

```bash
python _build/deploy_pcc.py       # 静态站（新增前端文件必须加进 FILES 清单！）
python _build/deploy_server.py    # 数据服务（改过 server.py 才需要）
python _build/verify_all.py --full
```

## 9. 新增一类数据/事件

以"作业打勾"这个改动为例，完整链路是：

1. `core.js`：加存储键、读写函数、`emit('hw', {...})`、在 `apply()` 里实现该事件的归约
2. `core.js` 的 `snapshot()` / `applySnapshot()`：把新数据域纳入导入导出与检查点
3. `sync.js`：一般**不用改**（它是按事件类型透传的）
4. `student.js` / `parent.js`：加界面
5. `check_refs.py`：如果新增了视图容器，把视图名加进页面清单
6. `smoke_test.js`：加断言（含"重算结果一致"这类不变量）
7. `smoke_sync.js`：加"该事件跨设备收敛"的用例
8. `deploy_pcc.py` 的 `FILES`：新增前端文件要手动加
9. `PRD.md`：加条目 + 变更记录

## 10. 常见陷阱（都是真实踩过的）

| 坑 | 表现 | 正确做法 |
|---|---|---|
| **原生表单校验吞提交** | 输入框带 `pattern`/`required`/`maxlength`，不满足时 **`submit` 根本不派发** → 用户看到"点了没反应"（iOS 上提示气泡还常常看不见） | 去掉这些属性，校验全在 JS 做，并把错误**显示到页面上**；输入时做净化（全角→半角） |
| **中文输入法全角数字** | `１２３４` 让密码框彻底静默 | 同上，按长度截断 + 转半角 |
| **`speechSynthesis` 静默失败** | 设备没中文语音 / 侧边静音 / 定时器里的朗读不算用户手势 / 家长关了开关 —— **都不报错** | 显式 `pickVoice('zh-CN')`、订阅 `voiceschanged`、`cancel()` 后补 `resume()`、`onstart` 看门狗超时回调 `onFail(why)`、自动重试一次；**并且优先用真音频** |
| **`getVoices()` 首次为空** | 误判"设备没语音" | 空 ≠ 真没有，语音库是异步加载的；判断原因时要**重新挑一次语音** |
| **中文路径下 `cv2.imread` 返回 None** | 二维码校验静默失败 | 用 `np.fromfile` + `cv2.imdecode` |
| **`findstr` 查 UTF-8 中文** | 误报 MISS | 经 HTTP 取回后用 Python 按 UTF-8 解码再判断 |
| **PowerShell `*>` 重定向** | 写成 UTF-16，文本工具当二进制拒绝 | 让脚本自己写 UTF-8 日志 |
| **`docker exec nginx -t`** | 输出走 stderr，读 stdout 得空串 | 合并 stderr |
| **`deploy_pcc.py` 的 FILES 是手写清单** | 新增文件忘了加 → 线上静默 404 | 上传后逐条 sha256 比对（脚本已内置） |
| **`ackIds` 被当成冗余字段删掉** | 客户端永久重传那批事件 | 见 §5 |

## 11. 协作约定

- **截图/日志里不要带真实地址与凭证**：提交前扫一眼
- **凭证只放 `_build/site.local.json`**（已 gitignore），别写进脚本、别贴进文档
- 写文档时用占位符（`<部署机-局域网IP>`），真实值留在本机
- 关键设计决策要写清**为什么**（例如"注册表用 JS 而非 JSON，是为了 `file://` 下不被 CORS 拦"）
- 改完在 `PRD.md` 的变更记录登记：改了哪些 ID、验收结论
