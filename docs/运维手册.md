# 运维手册

> 适用范围：把整站部署到一台**常开的家庭机器**上，供家里的 iPad / 手机 / 电脑访问。
> 本文把那台机器统一叫**部署机**（本项目实际用的是一台 Windows PC）。
>
> **地址与凭证都不写死在脚本里**：所有脚本从 `_build/site_config.py` 读配置，
> 真实值放 `_build/site.local.json`（**不进仓库**），也可用环境变量提供。
> 初始化见 §2。本文中出现的 IP / 域名一律是占位符。

---

## 一、访问地址（部署后）

| 场景 | 地址 | 说明 |
|---|---|---|
| **家里的 iPad / 手机** | `http://<部署机-局域网IP>:8099/` | 首选。扫码或手输 |
| 户外（设备需接入 VPN） | `http://<部署机-VPN-IP>:8099/` | 平板通常没装 VPN 客户端，户外场景要另行解决 |
| 家长端 | `http://<部署机-局域网IP>:8099/parent.html` | **不要给孩子**，需要家长密码 |
| 数据服务（多端同步） | `http://<部署机-局域网IP>:8100/` | 家长端"多端同步"里填这个；**不需要给孩子** |

二维码由 `gen_qr.py` 生成，共三张：

| 文件 | 给谁 |
|---|---|
| `qr-ipad-lan.png` | 局域网入口，给孩子用 |
| `qr-parent-lan.png` | 家长中心，给家长用 |
| `qr-remote-wg.png` | VPN 入口，给自己远程用 |

> 这三个 png 已在 `.gitignore` 里 —— 它们承载你家的真实网络地址，不要提交到公开仓库。
> 期望值由同一份配置推导，`verify_qr.py` 会**真解码**校验内容。

第一次打开建议带一次版本参数绕开旧缓存：`http://<局域网IP>:8099/?v=1`，之后不用再变。

## 二、首次部署

### 2.1 准备配置（凭证不再硬编码）

```bash
cp _build/site.local.example.json _build/site.local.json
```

然后编辑 `_build/site.local.json`：

| 键 | 填什么 |
|---|---|
| `host` | 部署机的 VPN 内网地址（脚本默认走这条，通常更稳） |
| `host_lan` | 部署机的局域网地址 |
| `ssh_user` / `ssh_password` | 部署机的 SSH 账号（**只存在这个文件里**） |
| `web_port` / `api_port` | 静态站与数据服务的端口（默认 8099 / 8100） |
| `remote_*_dir` | 部署机上的目录（默认可直接用） |
| `remote_python` | 部署机上 python.exe 的绝对路径（装数据服务时才用） |

也可以用环境变量（适合 CI 或不想落盘）：

```
XYB_HOST / XYB_HOST_LAN / XYB_SSH_USER / XYB_SSH_PASSWORD / XYB_WEB_PORT / XYB_API_PORT
```

没配置就跑脚本时，会得到一句明确的报错，**不会**拿着示例值去连。

### 2.2 部署静态站

```bash
python _build/deploy_pcc.py
```

它会自己完成：建目录 → 上传文件 → **逐个校验 sha256** → 重建容器 →
`nginx -t` → 从部署机本机打局域网/VPN 两个地址 → 从本机经 VPN 打 HTTP 验证。
结果写在 `_build/deploy.log`。

### 2.3 部署数据服务（要用多端同步才需要）

```bash
python _build/deploy_server.py
```

它会：上传 `server.py` + 生成 `install_service.bat` → 重建计划任务
（`/sc onstart /ru SYSTEM`，**开机自启、不需要人登录**）→ 启动 → 端口监听确认 →
从部署机本机打三个地址验活 → 从本机经 VPN 验活。结果写在 `_build/deploy_server.log`。

> ⚠️ `deploy_pcc.py` 里的 `FILES` 是**手写清单**：新增前端文件必须手动加进去，
> 否则线上静默少一个文件。上传后的 sha256 逐条比对就是防这个的。

## 三、为什么值得部署（不只是"方便"）

双击 `index.html` 打开时走的是 `file://` 协议。学习模块放在 `modules/<id>/` 子目录里，
少数浏览器（尤其 Firefox）对 `file://` 的**跨目录 localStorage 做隔离** ——
结果是"模块里明明学了，回到工作台进度没记上"。

换成 HTTP 之后这个问题彻底消失：所有页面同源，`localStorage` 稳定共享。
所以部署不是可选项，是**数据可靠性的保险**。

## 四、线上形态

```
<部署机>: <站点目录>\                     ← nginx 容器只读挂载这里
├── index.html               孩子端（/）
├── parent.html              家长端（/parent.html）
├── manifest.webmanifest
├── assets\                  app.css / core.js / sync.js / student.js / parent.js /
│                            catalog.js / xyb-sdk.js / icon.svg
├── modules\                 _template / math-calc / pinyin-1（含 audio.js）
└── 一年级数独\               教程 html、可打印题库 docx

<配置目录>\default.conf                     ← nginx 配置（放在 web 根外面，避免被当静态资源暴露）
容器：nginx:alpine  宿主 <web_port> -> 容器 80  --restart unless-stopped
挂载：两者均 :ro（只读）

<数据服务目录>\server.py                    ← 数据服务（多端同步的后端）
<数据目录>\                                 ← config.json / events.jsonl / meta.json / versions\
计划任务：XYBDataServer  onstart + SYSTEM  python.exe server.py --port <api_port> --data ...
监听：0.0.0.0:<api_port>
看门狗：XYBDataServerWatch  每 10 分钟检查一次（见下）
```

> ### ⚠️ 数据服务必须配看门狗，否则会静默挂掉
>
> `XYBDataServer` 是 `/sc onstart` —— **只在开机时启动一次**，进程一旦退出就再没人管，
> 而且**开同步之前完全无感**（页面照常用，只是多端同步是死的）。
> 实测就踩过：9/14 手动跑过一次之后进程退出（`上次结果: 267014` = 任务被终止），
> 一直没人发现，直到 9/23 才发现 8100 无人监听。
>
> 所以另建了一条**看门狗任务**（不动原任务）：
>
> ```cmd
> schtasks /create /tn XYBDataServerWatch ^
>   /tr "cmd /c netstat -ano | findstr :8100 >nul || schtasks /run /tn XYBDataServer" ^
>   /sc minute /mo 10 /ru SYSTEM /rl HIGHEST /f
> ```
>
> 每 10 分钟查一次端口，不在就把它拉起来。查这两条任务：
>
> ```cmd
> schtasks /query /tn XYBDataServer /v /fo LIST
> schtasks /query /tn XYBDataServerWatch /v /fo LIST
> ```
>
> 「上次结果」对照：`0` = 正常；`267014` = 任务被终止；`267011` = 尚未运行。

**刻意没上传的东西**（共省下约 2 MB 和 91 次传输）：

| 没传 | 为什么 |
|---|---|
| `一年级数独\*.mp3`（91 个） | 音频已 **base64 内嵌**进教程 html（代码里是 `audioPack()` + `data:audio/mpeg;base64,`），散装 mp3 只是构建中间产物 |
| `.workbuddy\` | 本地记忆与临时脚本，与运行无关 |
| `_build\`、`docs\` | 构建工具链和文档，不需要给孩子访问 |

> **判定方法**：上传大目录前先 grep 一下页面到底引用的是相对路径还是内嵌数据。
> 本项目里 `grep -c "data:audio"` 命中、`grep "\.mp3"` 只命中注释级引用 → 判定为内嵌，可以放心跳过。

## 五、日常更新流程

```bash
# 1) 本地改完先跑验证（静态四关）
python _build/verify_all.py

# 2) 部署（改过页面才需要；改过 server.py 再加 deploy_server）
python _build/deploy_pcc.py
python _build/deploy_server.py

# 3) 发布后连线上一起验
python _build/verify_all.py --full

# 4) 平板/手机刷新即可（配了 no-cache，不用清缓存、不用换 URL）
```

只想更新页面、不重建容器也行 —— nginx 直接读挂载目录，SFTP 覆盖对应文件即可，**不用重启容器**。

单独跑某一项：

| 脚本 | 用途 |
|---|---|
| `_build/verify_all.py` | **一键跑完所有验证关卡**（`--full` 含服务端与线上），日志 `_build/verify_all.log` |
| `_build/deploy_probe.py` | 只探测：连通性、端口占用、镜像、已有容器（写 `_build/probe.log`） |
| `_build/verify_http.py` | 只验证线上：UTF-8 特征串 + catalog 可达性 + 缓存头 + 数据服务鉴权（写 `_build/verify3.log`） |
| `_build/test_sync_server.py` | 数据服务 API 测试：本机临时实例，**不依赖部署机**（写 `_build/test_server.log`） |
| `_build/e2e_server_pcc.py` | 在部署机上做数据服务端到端（含清场，跑完把口令清掉等你重设） |
| `_build/gen_qr.py` | 重新生成三张二维码（改完跑 `verify_qr.py` 真解码校验） |
| `_build/build_video_index.py` | 扫描 `videos/` 生成清单 + 编码体检 |
| `_build/deploy_videos.py` | 上传视频（增量 + sha256 校验，见 §5之二） |

## 五之二、放学习视频（视频学堂）

视频和页面文件不一样：**体积大、常含版权素材、不能进 git**，所以单独一条通道。

### 方式一：一条命令（推荐）

```bash
# 加一个（自动归类、编号、体检编码）
python _build/add_video.py "D:\下载\认识图形.mp4" --subject 数学 --title "认识图形"
# 加完直接传上服务器
python _build/add_video.py "D:\下载\a.mp4" --subject 语文 --upload
# 批量：整个目录都加进某学科
python _build/add_video.py --dir "D:\下载\学习视频" --subject 科学 --upload
# 看现状 / 只看计划
python _build/add_video.py --list
python _build/add_video.py "D:\下载\a.mp4" --subject 数学 --dry-run
```

它会：复制到 `videos/<学科>/NN-标题.mp4`（**重名自动顺延，绝不覆盖**）→
解析时长与编码 → 重新生成清单；`--upload` 再走上传。
给 `--desc` 会写进 `videos/videos.json`（可选的手工元数据文件）。

> ⚠️ `--upload` 需要 **paramiko**，请用装了它的 Python 跑
> （报 `No module named paramiko` 就是这个原因）。不加 `--upload` 时只重新生成清单，
> **本地/局域网能看，但没上传的线上还是旧清单** —— 脚本会明确提示这一点。

### 方式二：手动放（等价）

```bash
# 1) 按学科放进 videos/（一级目录名 = 学科，与工作台学科一致最好）
#      videos/语文/01-拼音儿歌.mp4
#      videos/数学/认识图形.mp4
#    文件名开头的 "01-" / "1." 会被当成排序号剥掉，其余部分就是标题。
#    想手改标题/简介/封面，加一个 videos/videos.json（可选）。

# 2) 生成清单（同时做编码体检，iPad 放不了的会报警）
python _build/build_video_index.py

# 3) 上传（增量：远端已存在且大小一致的自动跳过；--dry-run 只列计划）
python _build/deploy_videos.py
python _build/deploy_videos.py --dry-run      # 只看要传什么
python _build/deploy_videos.py --force        # 全部重传
python _build/deploy_videos.py --prune        # 顺手删掉远端多出来的
```

**为什么清单要"预生成"**：纯静态页面**列不了目录** —— `file://` 下没有目录 API，
nginx 不开 autoindex 也拿不到文件列表。所以清单是脚本扫描生成的
（`modules/video-1/videos.js`），这也顺带能算时长、做编码体检。

### iPad 兼容（最容易踩的坑）

**iPad Safari 只稳吃 H.264（avc1）+ AAC（mp4a）的 mp4。**
HEVC / AV1 在 Safari 上多半**直接黑屏且不报错** —— 所以生成清单时会提前体检，
不兼容的视频会在清单里标 `ok:false`，页面上也会打一个"格式可能不支持"的标记。

需要转码时（本机要先有 ffmpeg）：

```bash
ffmpeg -i 输入.mp4 -c:v libx264 -profile:v high -pix_fmt yuv420p -c:a aac -b:a 128k 输出.mp4
```

自查单个文件：

```bash
python _build/build_video_index.py      # 输出里会列出每个视频的编码与结论
```

### ⚠️ 上传速度的现实（先看这个，再决定怎么传）

实测（从**办公网**经 WireGuard 传到家里那台）：

| 方式 | 速率 |
|---|---|
| 单流 SFTP | **0.53 MB/s** |
| 6 路并发 | 0.72 MB/s —— **没提速，还把 SSH 连接压垮了**（`Socket exception 10053`） |

→ **瓶颈是带宽，不是延迟**（家庭 WG 是星型 + 云服务器中转），并发没有意义。
7.2 GB 的视频**要传约 3.8 小时**。

所以按场景选：

- **省事**：`python _build/deploy_videos.py` 挂着跑。它是**增量**的 ——
  中断了、关机了、重跑了，都会**跳过已传完的**（按大小判断），不会从头再来。
  日志 `_build/deploy_videos.log` **每传完一个就写一次**，可以随时看进度。
- **最快**：把 `videos/` 整个目录拷到 U 盘/移动硬盘，插到部署机上直接复制到
  `<视频目录>`（默认 `D:\xiaoyuebing-videos`）。7GB 在 USB3 上是**分钟级**。
- **想后台无人值守**：Windows 的计划任务（`schtasks`）在这台开发机上被安全策略挡着，
  换一台机器或让计划任务从部署机侧发起即可。

### nginx 侧

视频放在**部署机的 D 盘**（C 盘留给系统），由 `deploy_pcc.py` 挂进容器：

```
D:\xiaoyuebing-videos  =>  /usr/share/nginx/html/videos  (ro)
```

`deploy_pcc.py` 生成的 conf 里，`/videos/` 单独配了
`Cache-Control: public, max-age=3600`（页面仍是 `no-cache`）——
视频大且基本不变，允许浏览器缓存一小时，拖动进度条时少一些往返。

## 七、必须知道的限制

1. **每台设备的数据默认是独立的**。`localStorage` 不跨设备。开启多端同步后会收敛到同一份记录
   （服务端不合并、只追加事件 + 各端重算，所以不会因合并规则写错而丢数据）；
   **家长密码仍然各设备独立**，iPad 上要单独设一次。
   不开同步时想合并，就导出 JSON 再在另一台导入。
2. **静态站依赖容器，而容器依赖有人登录**：Docker Desktop 只挂在用户启动项（HKCU Run），
   `com.docker.service` 是 `DEMAND_START`。部署机重启后若停在登录界面，nginx 容器不会起来。
   **但数据服务不受这条影响** —— 它走计划任务 `onstart + SYSTEM`，开机即起。
   所以"刚重启、没人登录"时，可能是同步通而页面打不开，反之不会发生。
3. **出了家门局域网地址就打不开**：局域网 IP 只在家庭网内有效；户外要用 VPN 地址，
   前提是设备已接入 VPN —— 而多数平板默认没装客户端，所以远程场景需另行解决
   （装 VPN 客户端并导入配置，或改用 Tailscale 之类的方案）。
4. **数据服务是单点**：部署机关机/服务没起时同步停摆，但学习功能完全不受影响
   （事件攒在本地 `outbox` 里，联网后自动补交，服务端按事件 id 去重）。
5. **不要把数据服务端口暴露到公网**：它是家庭内网方案，`http` 明文传输，
   口令哈希会被中间人看到。公网场景应换成 HTTPS 或走 VPN。
6. **家长密码是"防孩子"级别**：哈希存本机，不防有心人。

## 八、踩过的坑（每条都真实踩过）

1. `findstr` 查 UTF-8 中文会**误判 MISS**（它按 ANSI 解码）。要验证中文内容，
   必须经 HTTP 取回后用 UTF-8 解码在 Python 里查。
   同理，`deploy_pcc.py` 里那句 PowerShell 的 `$r.Content -match '小悦饼'` **恒为 False**
   —— 那是 PowerShell 按非 UTF-8 解码响应体的老问题，**不能据此判定内容没生效**，
   看 `verify_http.py` 的结论。
2. `docker exec ... nginx -t` 的输出走 **stderr**，只读 stdout 会得到空字符串。
3. PowerShell 的 `*>` 重定向把输出写成 **UTF-16**，用文本工具看会当成二进制文件。
   子脚本自己写 UTF-8 日志最稳。
4. **本机没装 paramiko 时别用系统 python**：`deploy_*.py` 需要 paramiko，
   建议用一个装了它的虚拟环境跑（见 `docs/开发手册.md` §6）。
5. **覆盖失败但看起来"没报错"是最坑的情况** —— 所以 `deploy_pcc.py` 内置了逐文件 sha256 比对。

## 九、数据备份与恢复

### 9.1 备份

| 备份什么 | 在哪 | 怎么备 |
|---|---|---|
| 孩子的学习数据（浏览器端） | 各设备 `localStorage` | 家长端 → 💾 数据备份 → **导出学习数据**（JSON，含错题本与作业） |
| 服务端权威副本 | `<数据目录>\` | 直接拷目录：`state.json` + `versions\` + `meta.json` |
| 代码与内容 | 这个仓库 | `git`（内容都是文本，diff 清晰） |

**建议**：换设备/重装浏览器前先导出一次 JSON；服务端数据目录可以定期拷一份到别处。

### 9.2 恢复

1. **单台设备丢了数据**：家长端 → 💾 数据备份 → 导入 JSON → 全部记录回来（错题会重算去重键）。
2. **误清空/改坏了**：家长端 → ☁️ 多端同步 → **历史版本** → 选一个时间点回退。
3. **服务端数据目录丢了**：从备份拷回 `state.json` 与 `meta.json`，重启计划任务；
   客户端下次同步会全量重拉。

> 回滚的机制是"截断日志 + `gen+1`"，客户端发现 `gen` 变化会丢弃本地事件缓存重新拉取。
> 所以回滚是**强一致**的，不会出现"一半新一半旧"。

## 十、多端同步的开通与排查

### 10.1 开通

家长端 → ☁️ 多端同步 → 地址填 `http://<部署机-局域网IP>:8100` → 设一个 4 位以上家庭口令
→「连接并开启」。第一台设备按提示选"以本机为准"或"以云端为准"。

### 10.2 排查顺序（成本从低到高）

| 症状 | 先查什么 |
|---|---|
| 点"连接并开启"没反应 | 现在就**不会静默**了：页面会显示具体错误。看提示里的原因 |
| 提示"地址不对/连不上" | 浏览器直接访问 `http://<IP>:8100/api/ping`，能返回 JSON 才说明网络通 |
| 能 ping 通但连接失败 | 口令不对（401）。口令是**每台设备各存一份哈希**，换口令要重新输入 |
| 状态显示已连接但数据没过来 | 看"待发送 N 条"；若一直不清零，可能是服务端版本旧（缺 `ackIds` 回报） |
| 两台设备数据不一致 | 各端点一次"立即同步"；仍不一致就看"记录点 rev"是否相同 |
| 服务端不可达 | 部署机是否开机、计划任务 `XYBDataServer` 是否在运行、VPN 是否连上 |

> **为什么不会静默丢数据**：服务端只做"按到达顺序追加 + 按 id 去重"，
> 客户端每次用「服务端事件 + 本地 outbox」**重算**一遍状态。
> 事件集合与顺序一致 → 归约结果必然一致，所以不存在"合并规则写错丢数据"。

## 十一、历史遗留：`sudoku-web` 容器（8000 端口）

部署机上可能还有一个更早的容器 `sudoku-web`，发布在 **8000** 端口 —— 那是数独单文件时代的产物，
内容已被现在的工作台覆盖（工作台里点"数独闯关营"进的是同一份教程，还能顺手带上进度记录）。

它**仍在运行、无害**，但有两个潜在混淆：

- 如果设备上收藏过 `http://<IP>:8000/`，打开的还是那份**不记录进度**的旧页面；
- 它是**另一份拷贝**，改工作台里的数独不会同步过去。

**建议**：确认没人用 8000 之后 `docker rm -f sudoku-web` 清掉，统一从一个入口进。
（确认前不要删正在跑的东西。）
