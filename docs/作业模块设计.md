# 作业模块设计方案（v1，待拍板）

> 输入：老师 9/16、9/17、9/18 三天的「温馨提示」原文
> 学生：小学一年级（北京昌平）
> 结论先给：**这个模块不该做成"老师原文的公告牌"，而应该是"孩子的一日作业清单 + 家长的录入台"。**

---

## 一、教材口径（用作业里的页码反推验证过）

| 科目 | 版本 | 当前进度（从作业内容反推） |
|---|---|---|
| 数学 | **北京版（2024 新版）** 一年级上册 | 第一单元「5以内数的认识和加、减法」：认识1~5（16–18页）→ 几和第几（19页）→ 大于、小于和等于（20–22页） |
| 语文 | **统编（部编）版** 一年级上册 | 第一单元 识字（《日月山川》等）→ 语文园地一 |
| 英语 | 北京版（按昌平口径），本周作业里还没出现 | 待观察 |

> 验证依据（不是猜的）：作业写"学习第19页《几和第几》"，北京版该课**正好在第19页**；
> 9/18"完成21页三种符号书写"落在**大于、小于和等于（20–22页）**区间内；
> 9/16"复习1-5书写、完成18页"落在**认识1~5（16–18页）**末尾。三处连续命中，可以确认出版社。

**这件事对模块的意义**：每条作业都能挂上"教材位置"，于是可以顺带回答家长最关心的两个问题 ——
"讲到哪了""这一课还有没有没掌握的地方"。建议在数据里保留 `textbook` 字段，为以后的"进度地图"留口子。

## 二、三天原文拆出来的结构（这是设计的依据）

### 2.1 骨架（三天高度一致）

```
9月18日温馨提示                      ← ① 一天一条，标题带日期
├── 【数学】                          ← ② 学科板块
│    今日学习任务：…（学了什么）        ← ③ 第一层：课堂进度
│    🏠回家学习任务：                  ← ④ 第二层：回家清单（可打勾的真正内容）
│      1. … 2. …
├── 【语文】
│    今日语文任务：…
│    1️⃣2️⃣3️⃣ …
├── 【美文朗读】                        ← ②′ 偶发第 4 个板块（9/16 出现过）
└── 【班级通知】                        ← ②″ 通常最后一个板块
     1. … 2. …
```

### 2.2 三类条目（必须分开处理）

| 类型 | 例子 | 给谁看 | 能不能打勾 |
|---|---|---|---|
| **学科·课堂进度** | "课上学习了＞＜＝，完成21页书写" | 家长（了解进度）、孩子（回顾） | ✗ 只读 |
| **学科·回家任务** | "自愿练习＞＝＜书写""背一背：一片两片三四片…" | **孩子**（这就是作业） | ✅ |
| **班级通知** | "9月20日疫苗接种""发3顶小黄帽，写班级姓名" | **家长**为主 | 部分能（带东西类可打勾） |

### 2.3 回家任务的动词是有限集合（重要发现）

三天里出现的任务动词，数一数其实很少：

`读一读 / 指读`、`背一背`、`练一练 / 写一写`、`说一说 / 想一想`、`做一做`（动手实践）、
`带回来 / 带去`、`完成改错`

**这对一年级特别关键**：孩子识字量还不够自己读句子，但**看懂图标 + 听懂一个词**是没问题的。
所以每个任务条目 = **图标 + 动词（音频）+ 一句短话**，孩子不用认字也能知道要干什么。

> 顺带解决一个我们已经踩过的坑：任务动词是**有限集合**（约 10 个），
> 可以像拼音那样预生成音频包（10 条 ≈ 60KB），于是"没声音"不再取决于设备有没有语音合成。

### 2.4 其他必须建模的细节（三天都出现过）

| 现象 | 例子 | 设计处理 |
|---|---|---|
| **自愿 / 必做** | "均为自愿完成""自愿练习＞＜＝" | `must: false`，界面标"可以做，也可以不做" |
| **页码/资源引用** | 数学书21页、101页附页、语文14页二线格、《小猫种鱼》 | `ref` 字段（书/页/要带的物品） |
| **未来日期的事** | 9月20日（周日）疫苗接种 | `due: '2026-09-20'`，到期前提醒 |
| **跨天的事** | "安全责任书，请明日带回" | 次日自动置顶为"要做完的旧事" |
| **家长专属** | 私信老师、留意剪刀安全、帽子写姓名、家长配合路队 | `forParent: true`，**不塞给孩子** |
| **原文留档** | 老师原文整段 | `raw` 字段保留，解析错了能对照，也能改规则重解析 |

## 三、设计目标

**给孩子（核心）**
1. 每天回家打开就是**一屏作业**，不用翻聊天记录、不用问家长
2. 每项**图标 + 短句 + 一个大勾**，点一下就打勾，打完有反馈（星星/贴纸）
3. 全部做完 → 明确的"今天作业清空啦"的成就感，接上现有徽章体系
4. 听不懂的动词可以点小喇叭（预生成音频，不依赖设备语音合成）

**给家长**
1. 录入要**省事**：老师原文粘贴进去 → 自动拆成清单 → 改两下就完事（一分钟以内）
2. 能看到"昨天/本周的作业"和孩子的打勾情况
3. 给家长看的事（疫苗、带书、写姓名）单独一块，不跟孩子的任务搅在一起

**明确不做**
- ❌ 不做"把老师原文直接给孩子看"（一年级读不懂，体验最差）
- ❌ 不做在线提交/拍照上传（没有服务端存储需求，孩子的作业本在书包里）
- ❌ 不把作业完成算进"学习时长/正确率"（那是课程模块的统计口径，混进去会失真）

## 四、数据模型（草案）

存在本地，命名空间照旧 `xyb.v1.*`：

```js
xyb.v1.homework = {
  version: 1,
  days: [
    {
      date: '2026-09-18',              // 老师发布日（也是孩子做作业的那晚）
      teacher: '',                      // 可选：老师名字
      raw: '9月18日温馨提示\n【数学】…', // ★ 老师原文，留档
      parsedAt: 1758000000000,
      blocks: [
        {
          subject: '数学',               // 数学 / 语文 / 英语 / 美文朗读 / 班级
          textbook: { book: '北京版数学一上', page: 21, unit: '一、5以内数的认识和加、减法' },
          learned: '认识了 ＞ ＜ ＝ 三种符号，会比较数字大小，完成 21 页书写',
          tasks: [
            { id: 'h-0918-1', icon: '✍️', verb: '写一写', text: '练习 ＞ ＜ ＝ 的写法',
              must: false, ref: '数学书 21 页', doneAt: 0 },
            { id: 'h-0918-2', icon: '🧩', verb: '做一做', text: '拿两样东西比多少，用大于小于说一说',
              must: false, doneAt: 0 }
          ]
        },
        {
          subject: '班级',
          tasks: [
            { id: 'h-0918-3', icon: '💉', verb: '记一记', text: '9月20日（周日）打疫苗',
              due: '2026-09-20', forParent: true, doneAt: 0 },
            { id: 'h-0918-4', icon: '🧢', verb: '带回来', text: '帽子上写好班级和姓名',
              forParent: true, doneAt: 0 }
          ]
        }
      ]
    }
  ]
}
```

要点：
- **`raw` 一定保留**：解析不可能 100% 准，家长要能对照原文；改解析规则后能一键重解析。
- **`doneAt` 直接写在任务上**（而不是另开一张表）：同步的时候就是一个事件 `{t:'hw', id, on}`，
  现有的事件日志模型天然支持 —— 和错题本订正是同一套机制。
- `forParent` / `must` / `due` 三个标记承担了"该谁看、要不要做、什么时候前做完"的全部语义。

## 五、录入方式：三个选项

| 方案 | 怎么做 | 优点 | 代价 |
|---|---|---|---|
| **A. 粘贴 + 自动解析**（推荐） | 家长在家长端粘贴老师原文 → 本地正则按【】分块、按 1️⃣2️⃣/1./① 分条 → 预览可改 → 保存 | 一分钟搞定；**全离线，不依赖任何 AI/服务端**；原文留档 | 解析规则要覆盖老师的花式排版（1️⃣、①②、●、缩进…），需要留"手动改"的后路 |
| B. 逐条手动加 | 家长点"加一项"，选学科/图标/写一句话 | 结构永远正确 | 每天 5–8 项都要手打，坚持不下来 |
| C. 只贴原文给孩子看 | 家长端贴纯文本，孩子端显示整段 | 零成本 | 一年级读不了长段落，等于没做 |

**推荐 A**：解析是"尽力而为"，但**预览可编辑**兜底，且原文留档。
解析要能认出来的东西：板块标题、序号（1️⃣/1./①/●/–）、"自愿"字样、页码（第21页/101页附页）、
未来日期（9月20日）、"明日/明天"这类相对时间。

## 六、界面：孩子端与家长端

### 6.1 孩子端（两个位置都建议做，成本都不高）

| 位置 | 形态 | 为什么 |
|---|---|---|
| **首页顶部第一张卡** | "今天的作业：还有 3 项没做" + 进度环，直接展开前两项可打勾 | 每天回家第一眼看到的就是它，优先级高于"课程" |
| **新增「📌 作业」Tab**（底部第 5 个） | 完整清单：按学科分组、大图标、打勾、完成后庆祝 | 认字少的孩子需要更简单的一屏 |

每个任务条目：
```
[✍️]  写一写        ← 图标 + 动词（可点听）
      练习 ＞＜＝ 的写法    ← 一句短话（≤14 字）
      [ 打勾 ]              ← 大按钮，点了有音效/动画
```

### 6.2 家长端（新增「📌 作业」面板）

- **录入区**：粘贴框 + 「解析」→ 预览表格（每行可改文本、切"仅家长"、勾"自愿"）→ 「保存」
- **历史**：按日期倒序列出（可翻旧账、补作业）
- **家长待办**：把 `forParent` 的条目单独汇总一块（疫苗、带书、写姓名）
- **完成情况**：今天打勾了几项 / 本周完成率（**不进学习时长统计**）

## 七、和现有架构怎么接（重要建议）

**不建议做成 `modules/<id>/` 下的独立页**，而是做成**工作台内置视图**（像错题本那样），理由：

1. 作业是"每天要看、要打勾"的**核心数据**，不是一节课内容；放 modules/ 里要用 SDK 跨页面上报（绕）
2. 内置视图天然共享 `localStorage` 与多端同步（`core.js` 的 `emit/rebuild`）——
   新增一个事件类型 `hw` 就能让 iPad 和电脑看到同一份打勾状态
3. 内置视图可以直接上首页卡片和底部 Tab，不用做"点卡片跳转再回来"的往返
4. catalog 里**不用加条目**（避免和"课程内容"混在一起被搜索/筛选）

改动清单（预估）：
| 文件 | 改什么 |
|---|---|
| `assets/core.js` | 新增 `homework` 数据层（读写、解析、打勾、统计）+ 事件类型 `hw` + 徽章 |
| `assets/student.js` | 首页作业卡 + 「作业」视图 + 底部 Tab（移动端 5 个 Tab） |
| `assets/parent.js` / `parent.html` | 「作业」录入面板 + 历史 + 家长待办 + 完成率 |
| `assets/catalog.js` | 不动 |
| `_build/` | 解析函数要单独可测（放 core.js 里导出，smoke_test 直接喂三天的真实原文断言解析结果） |

## 八、已拍板的决策（2026-09-19）

| 问题 | 决定 |
|---|---|
| 录入方式 | **A 粘贴 + 自动解析**（预览可改，原文留档） |
| 孩子端位置 | **首页顶部卡 + 新增「📌 作业」Tab**（底部 5 个 Tab） |
| 家长专属条目 | **单独一块「要爸爸妈妈做的事」，只给家长**（孩子端只提示一句"还有 N 件要提醒爸爸妈妈"） |
| 「自愿」任务 | **一视同仁不区分** —— 解析时把"自愿/均为自愿完成"这类字样直接清掉，孩子看到的文案更干净 |

另外两项按建议默认做了：
- **原文留档 `raw` + 一键重解析**：家长端每天一行「重新解析」，改了解析规则能重跑
- 任务的 `full`（老师原文那句）留在家长端，孩子端只显示 `text`（≤24 字的短句）

## 九、实施结果（2026-09-19 已完成）

| 文件 | 改了什么 |
|---|---|
| `assets/core.js` | 新增作业数据层 + 解析器（`hwParse/hwUpsertDay/hwToggle/hwStats/hwPending`）；事件类型 `hw`；`snapshot/export/import/clear` 都带上作业 |
| `assets/student.js` / `index.html` | 首页顶部作业卡（只摆没做完的前 2 项）+ 「📌 作业」视图 + 底部第 5 个 Tab + 两处角标；点一下打勾，全做完撒彩带 |
| `assets/parent.js` / `parent.html` | 「📌 作业」面板：粘贴 → 解析预览（每行文字可改、可勾"给家长"、可删）→ 保存；已录入列表（重新解析/删除）；家长待办块（可直接打勾） |
| `assets/app.css` | 作业卡、任务行、预览行、粘贴框样式 |
| `_build/check_refs.py` | 孩子端视图清单加上 `homework`（`view-*`/`nav-*`/`tab-*` 三处都要有，脚本会强制） |
| `_build/smoke_test.js` | 新增 **[D] 作业模块** 段：用 9/17、9/18 的**真实原文**当用例（35 条） |

**解析器踩到并修掉的两个坑**（都写在代码注释里了）：
1. 语文那条 `1️⃣说一说：【六、八】的笔顺和组词` 里的 `【六、八】` 是内容里的引号 ——
   按全文正则切板块会凭空多出"六、八"板块。改成**只有行首的【xx】才算板块标题**。
2. `1️⃣`（键盘帽，U+0031 U+FE0F U+20E3）去掉 emoji 之后只剩"1 "，
   原来的"数字+点/顿号"判断认不出来 → 整条被当成课堂进度吞掉。
   改成序号识别四种写法：`1️⃣` / `①` / `1.` / `1：`。
3. 顺带：动词识别改成**先看开头 12 个字**再全句兜底，
   否则"实践小活动：找两样东西比一比，说一说谁多谁少"会被后半句的"说一说"抢走图标。

**下一步（待办）**：
- 任务动词的**预生成音频包**（读一读/背一背/写一写/做一做 ≈ 10 条），孩子点小喇叭就听懂要干什么
- 用更多天数的原文继续喂解析器（老师排版会变：`●`、缩进、合并成一行…）
- 「作业完成」的徽章（现在只有撒彩带，没进成就体系 —— 刻意不污染学习时长/正确率统计）
